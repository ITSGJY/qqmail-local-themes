# QQ邮箱本地主题切换

适用于新版 QQ 邮箱的 Tampermonkey 用户脚本，提供 **东方青绿、竹林清风、桃花微雨** 三种主题切换，支持记住选择及关闭本地换肤。

**说明：** 本项目只在浏览器本地修改 CSS 类名，不修改会员资格、账号数据或服务端权限。主题资源如果没有加载，添加类名不能保证外观完整显示。

## 安装
1. 安装 [Tampermonkey](https://www.tampermonkey.net/)。
2. 打开 [脚本源文件](./qqmail-local-themes.user.js)，复制到 Tampermonkey 新脚本中保存。
3. 刷新 `https://wx.mail.qq.com/home/index`，点击扩展菜单选择主题。
4. 选择「跟随网页设置」则刷新页面，恢复邮箱自己的主题逻辑。

## 特性
- 三种主题菜单，当前主题带勾选标记
- 本地存储选项
- MutationObserver 对抗页面重新覆盖 class
- 只匹配新版 QQ 邮箱，不采集邮件、无外部网络请求

## 测试
`node --test tests/themes.test.cjs`：模拟 DOM 的测试，不代替真实浏览器端到端验证。

## 控制台诊断（v2.2.0）
更新已有脚本并保存，刷新邮箱。按 F12 打开开发者工具的 Console（控制台），启用 Info、Warning、Error 级别，筛选 `QQ邮箱本地主题`。建议勾选 Preserve log（保留日志），以保留「跟随网页设置」刷新前的记录。

日常输出带版本号的启动、主题应用、切换及保存结果。网页重新覆盖主题时，`theme-repaired` 记录修复前后的主题类；此类日志最多每 10 秒输出一次，累计修复和省略条数保留在诊断信息中。读取或保存偏好失败、菜单 API 缺失或注册失败会有警告或错误。

在油猴菜单选择 **「输出诊断信息到控制台」** 可随时生成 `diagnostic` 快照。页面启动和切换主题后也会延迟约 1.5 秒自动检查，包含：

- 当前选择、页面加载状态、主题类是否匹配
- 背景层数量、声明了背景图片样式的层数
- 应用次数、网页覆盖后的修复次数、菜单数量和 GM API 可用性

`theme-check-inconclusive` 表示主题类或背景层不符合预期，可能是网页尚未加载完，也可能是 QQ 邮箱结构或样式发生变化。加载完成后可手动再输出一次。背景图片样式存在仅说明 CSS 声明存在，不能证明图片下载成功或视觉效果正确；图片加载问题请结合 Network 面板和页面截图检查。

日志仅在本地控制台输出，不读取邮件正文，也不输出账号、完整页面 URL、资源 URL 或原始异常内容，不发起诊断网络请求。报告问题时提供脚本版本、操作步骤和上述前缀的日志即可；如附截图，请遮挡邮件及个人信息。如果连 `startup` 都没有，先确认脚本已启用、保存后刷新了邮箱，并检查控制台筛选条件。

### 验证记录
v2.1.0：在 Edge 的 QQ 邮箱页面观察到竹林清风与东方青绿正常渲染；用户确认桃花微雨切换、刷新后保留选择、跟随网页设置恢复原生主题均正常。v2.2.0 的日志与诊断改动通过模拟测试，真实油猴环境需更新安装后验证。
